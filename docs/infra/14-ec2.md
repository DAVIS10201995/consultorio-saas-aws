# #14 EC2 Linux: qué administramos nosotros

Responsable: Persona B. Plantilla: `infra/cloudformation/02-ec2.yaml`.

## Modelo de responsabilidad compartida

En EC2, AWS administra el hardware, el hipervisor y la red física. **Todo lo que está dentro de la VM es nuestro.**

| Capa | Quién la administra | Cómo lo hicimos |
|---|---|---|
| Centro de datos, hardware, hipervisor | AWS | No aplica |
| Red de la VPC, grupos de seguridad | Nosotros | Stack `01-red.yaml`: solo el puerto 80 desde CloudFront, sin puerto 22 |
| Sistema operativo (Amazon Linux 2023) | Nosotros | AMI más reciente al crear; parches de seguridad automáticos cada día con `dnf-automatic` |
| Acceso de administración | Nosotros | SSM Session Manager con el rol de la instancia: sin llaves SSH ni puerto 22 abierto |
| Usuarios y permisos del sistema | Nosotros | Usuario de servicio `consultorio` sin sudo, sin shell y fuera del grupo `docker`. La API corre en el contenedor como UID 33 (`www-data`), no como root |
| Proxy inverso (nginx) | Nosotros | Puerto 80, `server_tokens off`, oculta `X-Powered-By`, añade `X-Request-Id` |
| Proceso de la aplicación | Nosotros | Servicio systemd `consultorio-api` que ejecuta el contenedor: sin capacidades de Linux, `no-new-privileges`, límite de 512 MB de memoria y 200 procesos, escucha solo en `127.0.0.1:8080` |
| Secretos de la aplicación | Nosotros | `/etc/consultorio/api.env` con permisos `0600` de root; nunca en la imagen ni en el repositorio |
| Registros | Nosotros | journald (Docker y systemd) y `/var/log/nginx/consultorio.access.log` con `req_id` y duración |
| Disco | Nosotros (AWS cifra) | gp3 de 20 GB cifrado con la llave administrada por AWS |
| Metadatos de la instancia | Nosotros | IMDSv2 obligatorio (sin tokens no hay credenciales del rol) |

## Qué crea la plantilla

- **Rol de instancia** `consultorio-ec2-api` con `AmazonSSMManagedInstanceCore`. Los permisos de DynamoDB y del bucket de respaldos se agregan en el stack de datos (#16).
- **EC2 t3.micro** en la subred pública, con el grupo de seguridad que solo acepta CloudFront.
- **IP elástica**, para que el DNS público, que es el origen de CloudFront, no cambie si la instancia se detiene.
- **Script de primer arranque** que instala y configura todo lo de la tabla, más 1 GB de swap porque la t3.micro tiene 1 GB de RAM.

## Despliegue

Requiere el stack `consultorio-red`.

```powershell
aws cloudformation deploy --region us-east-2 --profile consultorio --stack-name consultorio-ec2 --template-file infra/cloudformation/02-ec2.yaml --capabilities CAPABILITY_NAMED_IAM --tags Proyecto=consultorio-saas
```

`CAPABILITY_NAMED_IAM` hace falta porque la plantilla crea un rol IAM con nombre.

## Verificación y evidencias

1. **Entrar sin SSH.** EC2 > Instancias > `consultorio-api` > **Connect** > **Session Manager** > Connect. 📸 `14-ssm.png`
2. **El script terminó bien.** En la sesión:
   ```bash
   sudo tail -n 5 /var/log/cloud-init-output.log
   ```
   Debe decir `Preparacion terminada`.
3. **Servicios.**
   ```bash
   systemctl is-active nginx docker dnf-automatic.timer
   systemctl is-enabled consultorio-api
   curl -s localhost/health
   ```
   Lo esperado: `active` tres veces, `enabled` y `ok`. 📸 `14-servicios.png`
4. **Usuario sin sudo.**
   ```bash
   id consultorio
   sudo -l -U consultorio
   ```
   Lo esperado: no está en `wheel` ni en `docker`, y aparece "not allowed to run sudo". 📸 `14-usuario.png`
5. **IMDSv2 obligatorio.** Sin token, la petición se rechaza:
   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" http://169.254.169.254/latest/meta-data/
   ```
   Lo esperado: `401`.
6. **La IP pública no responde directo.** Desde tu computadora, `curl -m 5 http://<IpPublica>/health` debe agotar el tiempo de espera, porque el grupo de seguridad solo acepta CloudFront. 📸 `14-ip-directa.png`
7. **Parches.** `sudo dnf check-update --security` muestra pendientes (o nada); `systemctl list-timers dnf-automatic.timer` muestra la siguiente ejecución.

## Qué falta para el despliegue completo (#20)

- Definir `IMAGEN=` en `/etc/consultorio/servicio.env` y llenar `/etc/consultorio/api.env` con los datos de RDS y DynamoDB.
- Decidir de dónde baja la imagen: construirla en la VM desde el repositorio o publicarla en ECR (y dar al rol permiso de lectura).
- `systemctl start consultorio-api` y probar `/api/...` a través de CloudFront.
- Persona A: exponer una ruta de salud bajo `/api/` (por ejemplo, `/api/health`), porque CloudFront solo envía `/api/*` a la EC2. Laravel ya trae `/up`, pero queda fuera de esa ruta.
