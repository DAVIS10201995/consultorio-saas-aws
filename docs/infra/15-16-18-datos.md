# #15, #16 y #18 Datos: RDS, DynamoDB y respaldos

Responsable: Persona B. Plantilla: `infra/cloudformation/03-datos.yaml`. Script de cuentas: `db/roles.sql` (de Persona A, en `main`).

## Qué crea la plantilla

| Recurso | Configuración de seguridad | Prueba |
|---|---|---|
| RDS PostgreSQL 17 `consultorio-pg` (db.t4g.micro) | Subredes privadas, `PubliclyAccessible: false`, cifrada con KMS (`aws/rds`), parameter group con `rds.force_ssl=1` y TLS 1.2 mínimo, contraseña maestra en Secrets Manager | P06 |
| Grupo de seguridad de RDS (stack de red) | Solo acepta el puerto 5432 desde el grupo de la EC2 | P06 |
| Cuentas `consultorio_migrador` y `consultorio_app` (script SQL) | La app lee y escribe datos pero no puede crear tablas | P07 |
| DynamoDB `consultorio-bitacora-citas` | Cifrada con KMS (`aws/dynamodb`), PK/SK del #8, recuperación a un punto en el tiempo activada | P01, P11 |
| Política del rol de la EC2 | `PutItem` y `Query` sobre la tabla; **Deny** explícito a `DeleteItem`, `BatchWriteItem`, `UpdateItem` y `DeleteTable` | P08 |
| Bucket `consultorio-respaldos-<cuenta>` | Bloqueo de acceso público, cifrado, versionado, solo TLS, caducidad de 30 días. La EC2 solo puede **subir** a `pg_dump/`, no leer, listar ni borrar | P11 |

**Decisión:** usamos las llaves KMS administradas por AWS (`aws/rds`, `aws/dynamodb`) en lugar de una llave propia. El cifrado es el mismo y no cuesta; una llave propia cuesta 1 USD al mes y solo aportaría control sobre su rotación y su política.

## 1. Desplegar (consola de CloudFormation)

Requiere los stacks `consultorio-red` y `consultorio-ec2` en **CREATE_COMPLETE**.

1. CloudFormation > **Create stack** > **With new resources (standard)** > sube `infra/cloudformation/03-datos.yaml`.
2. **Stack name:** `consultorio-datos`. Deja los parámetros como están.
3. Agrega el tag `Proyecto` = `consultorio-saas` y dale **Next**.
4. Marca la casilla de recursos IAM y dale **Submit**.
5. Tarda de **10 a 15 minutos** por la RDS.
6. 📸 `15-outputs.png`: la pestaña **Outputs** (RdsEndpoint, TablaBitacora, BucketRespaldos).

Si falla, abre **Events** y busca la primera línea en rojo. Lo más probable con este tipo de cuenta: que la versión 17 no esté disponible (cambiar `VersionPostgres` a `16` y `FamiliaParametros` a `postgres16`) o que Secrets Manager no esté permitido.

## 2. Crear las cuentas de la base (desde la EC2)

1. Entra a la VM por **Session Manager**.
2. Instala el cliente de PostgreSQL y descarga el certificado de AWS para verificar el servidor:
   ```bash
   sudo dnf install -y postgresql17
   sudo curl -sSo /etc/consultorio/rds-ca.pem https://truststore.pki.rds.amazonaws.com/us-east-2/us-east-2-bundle.pem
   sudo chmod 644 /etc/consultorio/rds-ca.pem
   sudo chmod 755 /etc/consultorio   # solo hace falta en VMs creadas con la versión anterior de 02-ec2.yaml
   ls -l /etc/consultorio            # rds-ca.pem -rw-r--r--; api.env y servicio.env -rw-------
   ```
3. Consigue la contraseña maestra: consola > **Secrets Manager** > el secreto que empieza con `rds!db-` > **Retrieve secret value**. No la copies a ningún archivo.
4. Guarda el endpoint en una variable (copia `RdsEndpoint` de los Outputs del stack):
   ```bash
   EP=consultorio-pg.xxxxxxxx.us-east-2.rds.amazonaws.com
   ```
   En la prueba desde tu computadora, reemplaza `ENDPOINT` por ese mismo valor.
5. Copia el contenido de `db/roles.sql` (rama `main`) a `/tmp/roles.sql` en la VM y ejecútalo. Las contraseñas se escriben ocultas y no pasan por la línea de comandos:
   ```bash
   read -rsp "Clave migrador: " MIG_PW; echo; read -rsp "Clave app: " APP_PW; echo; export MIG_PW APP_PW
   ```
   ```bash
   psql "host=$EP dbname=consultorio user=postgres_admin sslmode=verify-full sslrootcert=/etc/consultorio/rds-ca.pem" -v ON_ERROR_STOP=1 -c '\getenv mig_pw MIG_PW' -c '\getenv app_pw APP_PW' -f /tmp/roles.sql; unset MIG_PW APP_PW
   ```
   Guarda las dos contraseñas en tu gestor; van en `/etc/consultorio/api.env` en el #20.

   Si falla en `ALTER DEFAULT PRIVILEGES` por permisos o membresía, ejecuta `GRANT consultorio_migrador TO CURRENT_USER;` como `postgres_admin` y repite el script: se puede correr varias veces.
6. 📸 `15-roles.png`: las dos cuentas con `rolsuper = f`, y la extensión `btree_gist` que necesitan las migraciones:
   ```bash
   psql "host=$EP dbname=consultorio user=postgres_admin sslmode=verify-full sslrootcert=/etc/consultorio/rds-ca.pem" -c "select rolname, rolsuper, rolcreaterole, rolcreatedb from pg_roles where rolname like 'consultorio_%'" -c "select extname from pg_extension"
   ```

**Nota del despliegue (2026-11-24):** las cuentas se crearon primero con un script equivalente, que después se retiró por duplicar `db/roles.sql`. Ese script ya incluía el `GRANT` de membresía, pero no `btree_gist`, que se agrega aparte con `CREATE EXTENSION IF NOT EXISTS btree_gist;`. Correr `db/roles.sql` en el #20 es seguro, pero cambia las contraseñas a las que se indiquen en ese momento.

## 3. Pruebas y evidencias

Todo desde la sesión de la EC2, salvo donde se indica.

### P06: TLS obligatorio y origen restringido

```bash
psql "host=$EP dbname=consultorio user=consultorio_app sslmode=disable" -c "select 1"
```
✅ Debe fallar con `no pg_hba.conf entry ... no encryption`. 📸 `15-sin-tls.png`

```bash
psql "host=$EP dbname=consultorio user=consultorio_app sslmode=verify-full sslrootcert=/etc/consultorio/rds-ca.pem" -c "select ssl, version from pg_stat_ssl where pid = pg_backend_pid()"
```
✅ Debe mostrar `ssl = t` y `TLSv1.3` o `TLSv1.2`. 📸 `15-con-tls.png`

Desde **PowerShell de tu computadora**:
```powershell
Test-NetConnection ENDPOINT -Port 5432
```
✅ Debe salir `TcpTestSucceeded : False`. La RDS no es alcanzable desde Internet. 📸 `15-desde-fuera.png`

### P07 (parte): la app no puede crear tablas

```bash
psql "host=$EP dbname=consultorio user=consultorio_app sslmode=verify-full sslrootcert=/etc/consultorio/rds-ca.pem" -c "create table intento(id int)"
```
✅ Debe fallar con `permission denied for schema public`. 📸 `15-app-sin-create.png`

La prueba de GRANT y REVOKE sobre una tabla de prueba es el #21.

### P08: DynamoDB con permisos mínimos

La EC2 usa las credenciales de su rol; no hay llaves en ningún archivo.

```bash
aws dynamodb put-item --region us-east-2 --table-name consultorio-bitacora-citas --item '{"PK":{"S":"ORG#prueba#CITA#1"},"SK":{"S":"EVT#2026-11-23#e1"},"tipo":{"S":"prueba"}}' --condition-expression "attribute_not_exists(PK)" && echo "PUT OK"
```
✅ `PUT OK`. Si se repite, falla con `ConditionalCheckFailedException`: esa es la idempotencia.

```bash
aws dynamodb query --region us-east-2 --table-name consultorio-bitacora-citas --key-condition-expression "PK = :pk" --expression-attribute-values '{":pk":{"S":"ORG#prueba#CITA#1"}}'
```
✅ Devuelve el elemento.

```bash
aws dynamodb delete-item --region us-east-2 --table-name consultorio-bitacora-citas --key '{"PK":{"S":"ORG#prueba#CITA#1"},"SK":{"S":"EVT#2026-11-23#e1"}}'
```
✅ Debe fallar con `AccessDeniedException ... with an explicit deny`. 📸 `16-dynamodb.png` (las tres salidas)

```bash
aws dynamodb scan --region us-east-2 --table-name consultorio-bitacora-citas
```
✅ También falla: `Scan` no está permitido, solo `Query` por clave.

### #18: el bucket de respaldos

```bash
B=consultorio-respaldos-$(aws sts get-caller-identity --query Account --output text)
echo prueba > /tmp/p.txt
aws s3 cp /tmp/p.txt s3://$B/pg_dump/prueba.txt && echo "SUBIDA OK"
aws s3 ls s3://$B/
aws s3 cp s3://$B/pg_dump/prueba.txt -
```
✅ La subida funciona; listar y descargar fallan con `AccessDenied`. La EC2 solo puede dejar respaldos, no leerlos ni borrarlos. 📸 `18-respaldos.png`

En la consola, S3 > el bucket > **Permissions**: "Block all public access: On". 📸 `18-bloqueo-publico.png`

## Retiro (#33)

Antes de borrar el stack, vacía el bucket (S3 > el bucket > **Empty**). CloudFormation no borra un bucket con objetos. Con el versionado activo, **Empty** borra también las versiones anteriores.
